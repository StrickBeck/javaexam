# Как разобраться в коде

## 1. Product: шаблон товара

Четыре поля: id, name, price, stockQuantity. Все private.

Конструктор принимает значения при создании объекта. this.name — поле текущего объекта, name — параметр. Геттеры читают данные, сеттеры проверяют и изменяют их.

В setPrice нельзя передать отрицательное значение, NaN или бесконечность. В setStockQuantity нельзя передать отрицательное число. Метод displayInfo возвращает строку с информацией о товаре.

## 2. Book, Electronics, Clothing: наследники

Book extends Product означает: книга является товаром. Поэтому ей не нужно заново объявлять цену, название и остаток.

super(id, name, price, stockQuantity) вызывает конструктор Product.

У Book добавлено одно поле author. У Electronics — brand. У Clothing — size.

В каждом классе есть @Override displayInfo(). Вызов super.displayInfo() получает общую информацию, к ней добавляется особенность вида товара.

## 3. User, Customer, Employee: пользователи

User хранит id, name, email, password, role.

Customer вызывает конструктор User с ролью Customer. Employee — с ролью Employee. Поэтому общие поля не дублируются.

checkPassword сравнивает введённую строку с сохранённой. toString выводит имя, email, роль и ID, но не пароль.

## 4. Order: что купил покупатель

Order хранит orderId, customer, products, totalAmount и receipt.

В products один элемент означает одну единицу. Если книга выбрана дважды, ссылка на неё встречается в списке два раза.

Конструктор проходит по списку и прибавляет цену каждого элемента к total. Одновременно добавляет строки в StringBuilder. Получившийся текст сохраняется в receipt. printReceipt() возвращает его для вывода.

Пример:

    [Book, Book, Mouse]
    3500 + 3500 + 15000 = 22000

getProducts() возвращает новый список с теми же ссылками, чтобы внешний код не очищал список заказа.

## 5. Shop: три списка

Shop хранит:

    ArrayList<User> users
    ArrayList<Product> products
    ArrayList<Order> orders

Конструктор добавляет демонстрационные данные. Методы addCustomer/addEmployee добавляют пользователей, addProduct — товар. login ищет email и проверяет пароль.

findProduct перебирает товары и возвращает найденный объект по ID. Если такого товара нет, метод сообщает об ошибке.

### placeOrder по шагам

1. Проверить покупателя и непустой список.
2. Убедиться, что все выбранные объекты есть в каталоге.
3. Для каждого товара посчитать, сколько раз он встречается в заказе.
4. Сравнить это число с остатком.
5. Создать Order.
6. Уменьшить остаток на единицу за каждый элемент выбранного списка.
7. Добавить Order в orders.

До шага 6 остатки не меняются. Поэтому отказ на шагах 1–5 не списывает часть товаров.

Сравнение chosen == product проверяет, что это один и тот же объект. Main добавляет в список ссылки, полученные от findProduct, поэтому такая проверка подходит.

## 6. Main: общение с пользователем

main создаёт Shop, Scanner и объект Main, затем вызывает run.

run показывает главное меню в цикле. switch выбирает действие. 0 завершает цикл.

login получает email и пароль. После успешного входа открывается меню нужного пользователя.

employeeMenu показывает действия сотрудника. customerMenu — действия покупателя.

placeOrder формирует обычный ArrayList<Product>. Каждый ID добавляет один объект. После 0 программа просит подтверждение и передаёт список в Shop.placeOrder.

readText читает целую строку. readInt преобразует её в int и повторяет запрос после неправильного ввода. readPrice так же читает double.

## Что запомнить

- Класс — описание, объект — конкретный экземпляр.
- private — контролируемый доступ к полям.
- extends — наследование.
- super — обращение к родителю.
- @Override — переопределение метода.
- ArrayList — изменяемый список.
- for — перебор данных, while — повторение меню.
- return — вернуть результат.
- throw — сообщить о недопустимой операции.
- try/catch — обработать ошибку и продолжить работу.
