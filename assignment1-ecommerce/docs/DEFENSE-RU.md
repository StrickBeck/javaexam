## Основные вопросы

**Как распределены обязанности классов?**  
User, Customer, Employee, Product, Book, Electronics, Clothing, Order описывают предметную область. Shop управляет списками и заказами. Main отвечает за консоль.

**Почему Customer и Employee почти пустые?**  
Общие поля уже есть в User. Подклассы задают свою роль через конструктор родителя.

**Почему User и Product не abstract?**  
Для задания достаточно обычных родительских классов. В магазине создаются конкретные Customer/Employee и три вида товаров, но запрет на создание базового объекта отдельно не нужен.

**Зачем private и сеттеры?**  
Например, stockQuantity нельзя сделать отрицательным через setStockQuantity: метод проверит значение до присваивания.

**Что означает final?**  
У ID, роли и данных готового заказа это запрещает повторное присваивание. У базовых сеттеров запрещает их переопределять. final у Shop означает, что от него не наследуются.

**Где полиморфизм?**  
В ArrayList<Product> лежат Book, Electronics и Clothing. В showProducts вызывается displayInfo, и Java выбирает переопределённый метод по реальному объекту.

**Что лежит в заказе?**  
Покупатель, список Product, ID, сумма и готовая строка чека. Каждый элемент списка — одна штука товара.

**Как купить несколько одинаковых товаров?**  
Выбрать один ID несколько раз. Shop посчитает, сколько раз товар встречается в выбранном списке.

**Что делают два цикла в placeOrder?**  
Внешний перебирает каталог. Внутренний считает выбранные единицы этого товара. Затем количество сравнивается с остатком.

**Почему при ошибке не списывается часть заказа?**  
Сначала проверяются все выбранные товары и создаётся корректный Order. После этого другой цикл уменьшает остатки.

**Почему чек не меняется после изменения цены товара?**  
Он формируется в конструкторе Order и сохраняется в String receipt. printReceipt возвращает уже готовую строку. Полный снимок товара отдельным классом не создаётся.

**Почему getProducts() возвращает new ArrayList?**  
Это копия списка. Её очистка не очищает внутренний каталог. Объекты Product в такой копии остаются теми же объектами.

**Почему double, а не BigDecimal?**  
Это знакомый тип из курса и небольшой учебный пример. Для финансового приложения с точным учётом копеек можно выбрать BigDecimal.

**Как проверяется пароль?**  
В учебной версии сравниваются строки через equals. Пароль хранится только в памяти текущего запуска и не выводится в списке пользователей.

**Что проверяют тесты?**  
Нормальную покупку, остатки, повторные товары, неверные данные, отмену, меню и доступ к полям. В отдельном test-файле 104 проверки. Он запускается отдельно от приложения.
